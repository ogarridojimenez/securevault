📘 Manual de usuario — SecureVault

🔷 ¿Qué es SecureVault?

SecureVault es un gestor de secretos cifrados. Permite almacenar, recuperar y gestionar de forma segura cualquier información sensible: API keys, contraseñas de bases de datos, tokens de servicios, certificados, etc.

Todo el contenido se cifra con AES-256-GCM antes de almacenarse en PostgreSQL. Solo el servidor (que posee la clave de cifrado en config.yaml) puede descifrarlo.

Proporciona tres formas de acceso:

  • Web UI — interfaz gráfica en el navegador
  • CLI — línea de comandos para automatización
  • API REST — integración programática desde otras aplicaciones

🚀 Comenzar

El servidor debe estar corriendo. Una vez iniciado, abre tu navegador en:

http://localhost:8080/

Requisitos:

  • Servidor SecureVault en ejecución
  • PostgreSQL 18+ con base securevault
  • Clave de cifrado en config.yaml
📌 Nota: La primera vez debes registrarte (email + contraseña). Luego inicia sesión con esas credenciales.

🌐 Web UI

Tras iniciar sesión verás varias pestañas:

📁 Vaults

Los vaults son carpetas que agrupan secretos por ámbito (ej: produccion, staging, desarrollo).

  1. Escribe un nombre para el vault
  2. Añade una descripción opcional
  3. Pulsa Crear
  4. Verás el vault en la tabla con el número de secretos que contiene
  5. Pulsa Eliminar para borrar el vault y todos sus secretos

🔐 Secretos

Los secretos son pares nombre/valor que se almacenan cifrados.

Añadir secreto:

  1. Selecciona un vault del desplegable
  2. Escribe un nombre (ej: db/password, api-key)
  3. Escribe el valor secreto
  4. Pulsa Guardar

Ver secreto: Pulsa Ver para mostrar/ocultar el valor descifrado.

Borrar secreto: Pulsa Borrar para eliminarlo permanentemente.

🔑 API Keys

  1. Escribe un nombre descriptivo (ej: ci-cd, monitoring)
  2. Pulsa Generar
  3. Copia la clave inmediatamente — solo se muestra una vez
  4. Pulsa Revocar para invalidar una API key

💻 CLI

El binario securevault-cli permite gestionar secretos desde la terminal.

Login

securevault-cli login -e usuario@email.com -p contraseña -s http://localhost:8080

Comandos principales

ComandoDescripción
loginIniciar sesión y guardar token
registerCrear una cuenta nueva
set <vault/name> <value>Guardar un secreto cifrado
get <vault/name>Recuperar y descifrar un secreto
list <vault>Listar secretos de un vault
exportExportar todos los secretos (JSON)
api-key create <name>Generar una API key programática

Ejemplos CLI

# Guardar contraseña de BD
securevault-cli set produccion/bd/password "postgres:SuperSecret123"

# Recuperar API key para usarla
export API_KEY=$(securevault-cli get opencodezen/api-key)
open code --api-key "$API_KEY"

# Exportar todo (para backup)
securevault-cli export > backup.json

🔒 Seguridad

  • Cifrado en reposo: AES-256-GCM, nonce único por secreto. Los datos en PostgreSQL son bytes cifrados, ilegibles sin la clave.
  • Autenticación: JWT con refresh tokens. Las contraseñas se almacenan con Argon2id.
  • API Keys: Tokens de acceso directo para automatización. Se pueden revocar individualmente.
  • Clave de cifrado: Se define en config.yaml. Sin ella, los datos son irrecuperables.

💡 Casos de uso

API key de terceros

securevault-cli set opencodezen/api-key "sk-..."
export OPENCODEZEN_KEY=$(securevault-cli get opencodezen/api-key)

Rotación de credenciales

securevault-cli set produccion/bd/password "nueva-contraseña-2026"

CI/CD

  1. Genera una API key desde SecureVault
  2. En tu pipeline, úsala para autenticarte

❓ FAQ

¿Puedo recuperar la clave de cifrado si la pierdo?

No. Haz backup seguro de config.yaml.

¿Los secretos se muestran en texto plano?

Solo cuando pulsas "Ver" explícitamente.

¿Puedo compartir un vault?

Actualmente no. Es una funcionalidad futura.
