📘 Manual de usuario — SecureVault

🔷 ¿Qué es SecureVault?

SecureVault es un gestor de secretos cifrados. Permite almacenar, recuperar y gestionar de forma segura cualquier información sensible: API keys, contraseñas de bases de datos, tokens de servicios, certificados, etc.

Todo el contenido se cifra con AES-256-GCM antes de almacenarse en PostgreSQL. Solo el servidor (que posee la clave de cifrado en config.yaml) puede descifrarlo.

Proporciona tres formas de acceso:

  • Web UI — interfaz gráfica en el navegador
  • CLI — línea de comandos para automatización
  • API REST — integración programática desde otras aplicaciones

🚀 Comenzar

El servidor debe estar corriendo. Una vez iniciado, abre tu navegador en:

http://localhost:8080/

Requisitos:

  • Servidor SecureVault en ejecución
  • PostgreSQL 18+ con base securevault
  • Clave de cifrado en config.yaml
📌 Nota: La primera vez debes registrarte (email + contraseña). Luego inicia sesión con esas credenciales.

🌐 Web UI

Tras iniciar sesión verás tres pestañas:

📁 Vaults

Los vaults son carpetas que agrupan secretos por ámbito (ej: produccion, staging, desarrollo).

  1. Escribe un nombre para el vault
  2. Añade una descripción opcional
  3. Pulsa Crear
  4. Verás el vault en la tabla con el número de secretos que contiene
  5. Pulsa Eliminar para borrar el vault y todos sus secretos

🔐 Secretos

Los secretos son pares nombre/valor que se almacenan cifrados.

Añadir secreto:

  1. Selecciona un vault del desplegable
  2. Escribe un nombre (ej: db/password, api-key)
  3. Escribe el valor secreto
  4. Pulsa Guardar

Ver secreto: Pulsa Ver para mostrar/ocultar el valor descifrado.

Borrar secreto: Pulsa Borrar para eliminarlo permanentemente.

⚠️ Los valores se muestran como •••••••• por defecto. Solo se descifran al pulsar "Ver".

🔑 API Keys

Las API Keys son tokens de acceso programático. Sirven para que scripts y aplicaciones se autentiquen sin usar contraseña.

  1. Escribe un nombre descriptivo (ej: ci-cd, monitoring)
  2. Pulsa Generar
  3. Copia la clave inmediatamente — solo se muestra una vez
  4. Pulsa Revocar para invalidar una API key

💻 CLI

El binario securevault-cli permite gestionar secretos desde la terminal. Ideal para scripts CI/CD y automatización.

Login

securevault-cli login -e usuario@email.com -p contraseña -s http://localhost:8080

Guarda un token de acceso en ~/.vault_token para comandos posteriores.

Comandos principales

ComandoDescripción
loginIniciar sesión y guardar token
registerCrear una cuenta nueva
set <vault/name> <value>Guardar un secreto cifrado
get <vault/name>Recuperar y descifrar un secreto
list <vault>Listar secretos de un vault
exportExportar todos los secretos (JSON)
api-key create <name>Generar una API key programática

Ejemplos CLI

# Guardar contraseña de BD
securevault-cli set produccion/bd/password "postgres:SuperSecret123"

# Recuperar API key para usarla
export API_KEY=$(securevault-cli get opencodezen/api-key)
open code --api-key "$API_KEY"

# Listar secretos de staging
securevault-cli list staging

# Exportar todo (para backup)
securevault-cli export > backup.json

📡 API REST

Todas las funcionalidades están expuestas como API REST. Usa JWT Bearer para autenticación.

Endpoints principales

MétodoRutaDescripción
POST/api/v1/auth/registerRegistrar usuario
POST/api/v1/auth/loginIniciar sesión → JWT
POST/api/v1/auth/refreshRenovar token
GET/api/v1/vaultsListar vaults
POST/api/v1/vaultsCrear vault
DELETE/api/v1/vaults/{id}Eliminar vault
GET/api/v1/vaults/{id}/secretsListar secretos (cifrados)
POST/api/v1/vaults/{id}/secretsCrear secreto
GET/api/v1/vaults/{id}/secrets/{sid}Obtener secreto (descifrado)
DELETE/api/v1/vaults/{id}/secrets/{sid}Eliminar secreto
GET/api/v1/api-keysListar API keys
POST/api/v1/api-keysGenerar API key
PUT/api/v1/api-keys/{id}/revokeRevocar API key

Ejemplo API (curl)

# 1. Login
curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"usuario@email.com","password":"MiPassword"}' | jq .

# 2. Obtener secreto
TOKEN="eyJhbGciOiJIUzI1NiIs..."
curl -s http://localhost:8080/api/v1/vaults/{vault_id}/secrets/{secret_id} \
  -H "Authorization: Bearer $TOKEN" | jq .

🔒 Seguridad

  • Cifrado en reposo: AES-256-GCM, nonce único por secreto. Los datos en PostgreSQL son bytes cifrados, ilegibles sin la clave.
  • Autenticación: JWT con refresh tokens. Las contraseñas se almacenan con Argon2id (hash resistente a GPU/ASIC).
  • API Keys: Tokens de acceso directo para automatización. Se pueden revocar individualmente.
  • Clave de cifrado: Se define en config.yaml. Sin ella, los datos son irrecuperables.
  • TLS: Se recomienda usar HTTPS en producción (proxy inverso con Nginx/Caddy).

💡 Casos de uso

API key de terceros

Guarda tu API key de OpenAI, Stripe, o cualquier servicio:

securevault-cli set opencodezen/api-key "sk-IgM5Nmbo61HTmEo..."
export OPENCODEZEN_KEY=$(securevault-cli get opencodezen/api-key)

Rotación de credenciales

Actualiza un secreto sin tocar código ni configuración:

securevault-cli set produccion/bd/password "nueva-contraseña-2026"

La app que lo consume solo necesita reiniciarse para obtener el nuevo valor.

CI/CD (GitHub Actions, GitLab CI)

  1. Genera una API key desde SecureVault (tab API Keys o CLI)
  2. En tu pipeline, úsala para autenticarte:
API_KEY=$(securevault-cli get ci-cd/api-key -s https://vault.tudominio.com)
export DATABASE_URL=$(securevault-cli get produccion/bd/password)

❓ Preguntas frecuentes

¿Puedo recuperar la clave de cifrado si la pierdo?

No. Si pierdes la clave de cifrado (config.yaml → encryption.key), los datos almacenados son irrecuperables. Haz backup seguro de ese archivo.

¿Los secretos se muestran en texto plano en la web?

Solo cuando pulsas "Ver" explícitamente, y solo en tu sesión. Por defecto se muestran como ••••••••.

¿Puedo compartir un vault con otro usuario?

Actualmente cada usuario tiene sus propios vaults. El uso compartido es una funcionalidad futura.

¿Es seguro usar HTTP en lugar de HTTPS?

Para desarrollo local sí. En producción, configura un proxy inverso con TLS (Caddy, Nginx, Traefik).
